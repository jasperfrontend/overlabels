### Claims
- **C1** [code] `TowerPhysics::offsetFor(null, $u)` returns a value in `[-UNAIMED_MAX, UNAIMED_MAX]`; `offsetFor('left', $u)` returns a value in `[-AIMED_MAX, -AIMED_MIN]`; `offsetFor('right', $u)` mirrors it.
- **C2** [code] `TowerPhysics::topples($xTop, $height)` is true exactly when `abs($xTop) + SWAY_PER_BLOCK * $height` exceeds `FALL_LINE`.
- **C3** [test] `TowerPhysicsTest` asserts C1, C2, `normalizeAim`, `swayAmplitude` and `leanSide`.
- **C4** [code] `TowerService::stack()` runs inside `Cache::lock("tower:stack:{$user->id}")`, reads the top block, adds the offset, and either creates one `TowerBlock` row or, when `topples()` is true, deletes every row for the user and creates none.
- **C5** [code] `TowerService::stack()` dispatches `TowerUpdated` with the landed block and the new height on a stack, and with `cleared = true`, height 0 and a `toppled` array on a topple.
- **C6** [code] `TowerBlock::record` is set on a block whose `position` exceeds `TowerService::currentRecord()` at placement; `first_record_block` in the returned facts is true only when that block's predecessor was not a record block.
- **C7** [code] When a new record is set and the user owns an `OptionSet` with slug `tower_record`, `TowerService::writeRecordRoster()` replaces its items with one display name per distinct login bottom to top via `ListItems::freshFromValues()` and dispatches `ListUpdated`.
- **C8** [code] `BotTowerController::store()` returns `reply: null` without an enabled `tower` `ExternalIntegration`, silently drops a chatter inside `settings.cooldown_seconds` (min 5, default 30) via `Cache::add`, and returns a spoken refusal without stacking when `StreamSessionService::isLive()` is false.
- **C9** [code] `BotTowerController::replyFor()` returns null for an ordinary stack, and a string on a topple, on `first_record_block` with a previous record above zero, and when the height is a multiple of ten.
- **C10** [code] `action: status` returns `TowerService::status()` behind a 10 second per-chatter `Cache::add` and does not check the live gate.
- **C11** [code] `BotTowerController::runPipeline()` stores an `ExternalEvent` with service `tower`, meters it, dispatches `ExternalEventStored`, applies the driver's control updates and the alert dispatch, and stamps `last_received_at`.
- **C12** [code] `TowerServiceDriver::getAutoProvisionedControls()` declares eleven controls; `PER_STREAM_CONTROL_KEYS` is `blocks_stacked_this_stream`, `tallest_tower_this_stream`, `topples_this_stream`.
- **C13** [code] `TowerServiceDriver::beforeControlUpdates()` writes `tallest_tower_this_stream` and `tallest_tower_record` only on a `stack` event and only when the height is strictly greater than the stored value.
- **C14** [code] `TowerServiceDriver::verifyRequest()` returns false unconditionally.
- **C15** [code] `StreamSessionService::resetTowerControls()` resets the three `PER_STREAM_CONTROL_KEYS` with `resetValue()` and a preserved `_at`, and calls `TowerService::clear()` only when the enabled integration's `tower_lifetime` setting is `per_stream` or absent.
- **C16** [code] `TowerService::clear()` deletes the user's blocks, resets `tower_height`, `tower_lean`, `tower_room` with `resetValue()`, and dispatches `TowerUpdated` with `cleared = true` and `toppled = null`.

### Unchanged
- `BotBuiltin::DEFAULTS` gains no `stack` or `tower` entry in this change, and the bot repo is untouched: the endpoint exists before any command can reach it, so nothing in chat changes until the verbs ship.
- `User::PREFERENCE_DEFAULTS['foreach_caps']` gains no `tower` key: the tower window is the fixed `TowerBlock::WINDOW` (`User::FOREACH_CAP_MAX`), so `Account.vue` and the caps type are not in the diff.
- `OverlayRenderer.vue` and `tagCompletions.ts` do not yet listen for `tower.updated` or complete `tower` fields; the render payload half ships here, the client half is a separate change.
- `CheckinServiceDriver`, `BotCheckinController` and `resetCheckinControls()` were the template for every file above and are not in the diff.

### Risk
A new table, created by migration on deploy. Registering `tower` lists it on `/settings/integrations` for every account immediately, unconnected; connecting it provisions eleven controls under the reserved `tower` prefix. No account can stack anything until the bot verbs ship.
