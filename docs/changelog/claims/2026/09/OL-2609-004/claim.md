### Claims
- **C1** [code] `ExternalServiceRegistry` maps `checkin` to `CheckinServiceDriver` and `displayName('checkin')` returns `Chat Checkin`.
- **C2** [code] `CheckinServiceDriver::verifyRequest()` returns false unconditionally, so the public webhook route (`ExternalWebhookController`, not in this diff) answers 403 for the checkin service.
- **C3** [code] `getAutoProvisionedControls()` declares exactly ten `source='checkin'` controls; `CheckinServiceDriver::PER_STREAM_CONTROL_KEYS` names the three per-stream ones (`checkins_this_stream`, `unique_countries_this_stream`, `farthest_checkin_km_this_stream`).
- **C4** [test] `IntegrationProvisioningTest` "connecting checkin provisions exactly the controls its driver declares" asserts a POST to the settings route creates the driver's exact key set.
- **C5** [code] `BotCheckinController::store()` sits behind `bot.internal` + `throttle:bot-internal`, enforces a per-chatter `Cache::add` cooldown, replies with usage on empty args and a miss message when `PlaceResolverService::resolve()` returns null, and upserts one `checkins` row per `(user_id, chatter_twitch_id)`.
- **C6** [code] `BotCheckinController::runPipeline()` passes the stored `ExternalEvent` as the third argument to `ExternalAlertService::dispatch()` and writes the `controls_updated` / `alert_dispatched` flags, mirroring `ExternalWebhookController::handle()` steps 9-11.
- **C7** [code] The `ExternalEvent::create` dedup insert runs inside a nested `DB::transaction` (savepoint), so a duplicate `message_id` cannot abort a surrounding Postgres transaction.
- **C8** [test] `BotCheckinTest` (17 tests) covers auth, gating, replies, pin move, per-stream counter semantics, cooldown, distance vs home, upward-only farthest, unique-country counting, same-second dedup, and the go-live reset in both pin-lifetime modes.
- **C9** [code] `StreamSessionService::resetCheckinControls()` selects `source='checkin'` with the explicit key list, resets via `resetValue()` (preserved `_at` carried on the broadcast), forgets `checkin:countries:{user_id}`, and dispatches a `cleared` `CheckinsUpdated` only when the integration's `pin_lifetime` is `per_stream`.
- **C10** [unverified] The two reset-behavior tests in `BotCheckinTest` were run against a tree with the `resetCheckinControls()` call commented out and both failed.
- **C11** [code] `CheckinsUpdated` broadcasts as `checkins.updated` on `PrivateChannel('alerts.'.$broadcasterId)` carrying one pin, the authoritative window count, and a `cleared` flag - never a full pin window.
- **C12** [code] `ExternalEventTemplateMapping::SERVICE_EVENT_TYPES` contains `'checkin' => ['checkin' => 'Chat Checkin']`; parity with `getSupportedEventTypes()` is pinned by the pre-existing `ExternalTriggerCatalogueTest`.
- **C13** [code] The checkin provider icon `0x1687` has `iconDistance() >= 7` against every other icon in `PROVIDER_ICONS` and the fallback.
- **C14** [code] Every `event.*` tag literal in the driver appears in `resources/help/reference/eventsub-tags/all-chat-checkin-events.md`, which is what `IntegrationEventTagDocsTest` checks for every registered service.

### Unchanged
- The twitch go-live reset block in `resetControls()` - the query on `source='twitch'` and `PER_STREAM_CONTROL_KEYS` - reads exactly as before; the checkin reset is a separate method called after it, and `StreamControlResetTest` is not in the diff.
- `ExternalWebhookController` is not in the diff: checkin requests reaching it flow through the existing verify step and fail there (C2), so no service-specific branch was added.
- `DonationIntegrationController` and its five subclasses are untouched; the structural guard in `IntegrationProvisioningTest` now exempts `checkin` alongside `gps` instead.
- `OverlayRenderer.vue` is not in the diff: `checkins.updated` broadcasts have no client listener yet - the overlay iterable is the next change.

### Risk
`!checkin` has no chat entry point until the bot builtin ships (the next change): the settings page
works and provisions controls, but the command is silently absent from chat. Existing user-created
controls keyed exactly `checkin` (none known) would now collide with the reserved key on creation
only - existing rows are unaffected.
