### Findings
- **F1** test narrower than claim - C6 says `globeTag.test.ts` asserts "empty south-polar rows", but `resources/js/globe/globeTag.test.ts:40-42 @925d2e9` checks only the last row (`MASK_ROWS - 1`); either widen the loop to the rows meant (17 are empty in the shipped mask) or record in a new claim that the test pins one row.
- **F2** compound claim with an uncheckable half tagged [code] - C5's provenance ("generated by bucketing every `geo_places` row") can only be checked against the gazetteer database, not the tree; `landmask.ts:19 @925d2e9` holds only the resulting base64. It should have been a separate `[unverified]` claim.
- **F3** claim false in part - C7's "template CSS owns all styling" does not hold @925d2e9: `checkinGlobe.ts:133` hard-codes the shell colour and opacity (fixed later by OL-2609-068), and `checkinGlobe.ts:202` sets inline `opacity: 0` on far-side labels, which is still there @HEAD. A new claim should say which styling is CSS-controlled; the inline opacity needs a separate decision.
- **F4** contradicts the record - `CLAUDE.md` (Template Tags) says "`TemplateDataMapperService::TAG_CATALOG` is the one and only declaration of a static template tag", but this change adds the static-overlay tag `[[[checkin_globe]]]` only as `GLOBE_TAG` in `resources/js/globe/globeTag.ts:15 @925d2e9`; `checkin_globe` is not in `app/` @925d2e9 or @HEAD, so the catalogue-derived `/tags` reference does not list it. The claim does not mention the rule. Either add the exception to `CLAUDE.md` or add a catalogue entry.
