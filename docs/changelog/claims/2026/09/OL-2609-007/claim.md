### Claims
- **C1** [code] `compiledHtml` runs `replaceGlobeTags()` on the authored source before `processTemplate` only when `templateUsesGlobe` matches; the placeholder literal contains no brackets, so neither the block engine nor the tag pass ever touches it.
- **C2** [test] `globeTag.test.ts` asserts the pre-pass replaces every occurrence, emits no brackets, leaves other tags alone, and matches only the exact literal.
- **C3** [code] The static-overlay `morphdom` call gains `onBeforeElChildrenUpdated` returning false for elements with `data-checkin-globe`, so the mounted canvas and label layer survive every `data.value` re-render.
- **C4** [code] three.js loads via dynamic `import('@/globe/checkinGlobe')` gated on `templateUsesGlobe`, and the `vite.config.mts` group emits it as a separate `globe` chunk; a build shows `globe-*.js` (~536 KB, 131 KB gz) absent from every entry chunk. A failed chunk logs a warning and leaves the placeholder empty.
- **C5** [code] The continent silhouette is `landmask.ts`: a 180x90 bitmask generated by bucketing every `geo_places` row into 2-degree cells (the tinker script is reproduced below), decoded at runtime - no map texture or network fetch.
- **C6** [test] `globeTag.test.ts` asserts the decoded mask has land at Amsterdam/Tokyo/Sao Paulo, ocean mid-Pacific and mid-Atlantic, empty south-polar rows, and that `latLngToUnitVector` returns unit vectors with poles on the y axis.
- **C7** [code] `mountCheckinGlobe()` reads `--globe-dot-color`, `--globe-dot-size`, `--globe-pin-color`, `--globe-rotation-seconds`, `--globe-tilt-degrees` off the placeholder; labels are DOM nodes with class `ol-globe-label` (`is-hidden` on the far side), so template CSS owns all styling.
- **C8** [code] `destroy()` cancels the animation frame, disconnects the ResizeObserver, disposes every geometry/material/texture and the renderer; `OverlayRenderer`'s `onUnmounted` calls it for every instance.
- **C9** [unverified] Verified visually in Chrome against the local build: a seeded 8-pin overlay rendered the rotating dotted globe with stalked labels, the foreach pin list, and control tags, with far-side pins occluded (shell opacity raised from 0.55 after the first screenshot showed them at full brightness).
- **C10** [code] `HelpCorpus::SHADOWED_PAGE_SLUGS` now contains `checkin`: the generated integration-controls reference entry owns the wikilink name and the guide at /help/checkin is reached by markdown links - the `chat` precedent, pinned by `HelpUnificationTest`.

### Unchanged
- `useConditionalTemplates.ts` and the tag parser are not in the diff: the pre-pass runs on authored source before both, which is what keeps the never-reparse rule intact (C1).
- The alert render path (`parseSource` for alert content and CSS) does not run the globe pre-pass; the tag is a static-overlay feature and renders as an empty no-op tag anywhere else.
- `keepNames` in `vite.config.mts` is untouched; three.js has no class-name guards, and the flag was already global.

### Risk
The globe chunk is ~131 KB gz on first use per browser source; it never downloads on overlays
without the tag. WebGL is required - OBS browser sources have it; a context-less browser shows an
empty placeholder.

Landmask regeneration script (run in tinker after a gazetteer refresh, then re-embed the base64):

```php
$cols = 180; $rows = 90; $bits = array_fill(0, $cols * $rows, 0);
DB::table('geo_places')->select('lat', 'lng')->orderBy('id')->chunk(20000, function ($places) use (&$bits, $cols, $rows) {
    foreach ($places as $p) {
        $col = max(0, min($cols - 1, (int) floor((($p->lng + 180.0) / 360.0) * $cols)));
        $row = max(0, min($rows - 1, (int) floor(((90.0 - $p->lat) / 180.0) * $rows)));
        $bits[$row * $cols + $col] = 1;
    }
});
$bytes = '';
for ($i = 0; $i < count($bits); $i += 8) {
    $byte = 0;
    for ($j = 0; $j < 8; $j++) { if (($bits[$i + $j] ?? 0) === 1) { $byte |= 1 << (7 - $j); } }
    $bytes .= chr($byte);
}
echo base64_encode($bytes);
```
